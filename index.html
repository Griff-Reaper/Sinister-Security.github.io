01

Prompt Shield

cyber-griffith/prompt-shield ↗

Tiered prompt-injection detector

A deterministic rule layer scores every prompt in under a millisecond and routes anything uncertain to an LLM adjudicator. The design intent was cost: pay for a model call only on the prompts the rules can't settle. At the band that actually ships, that intent does not survive measurement — 89.4% of prompts escalate, and the adjudicated path runs 1,473 ms at p50 against the rule layer's 0.17 ms. The rule layer is sub-millisecond. The detector is not.
Measured on a held-out set of 500 adversarial and 334 benign prompts.
eval/*.jsonl
prompt-shield / eval/attacks_test.jsonl · eval/benign_test.jsonl open on GitHub ↗ 
$ wc -l eval/attacks_test.jsonl eval/benign_test.jsonl
 500 eval/attacks_test.jsonl
 334 eval/benign_test.jsonl

# attacks span 40 technique IDs, 6 categories
# the 334 benign split 254 ordinary + 80 hard negatives
# ordinary/*: coding 50 · knowledge 40 · writing 30
#   casual 30 · math 25 · data 23
#   business 20 · translation 18 · summarization 18
The headline is ~62% recall at about 4% FPR, stated as a range on purpose. Three runs of an identical configuration measured recall 61.6 / 62.6 / 63.2% and FPR 3.9 / 3.9 / 3.3%. Quoting the 63.2% and the 3.3% together would be reporting the single best run as though it were the result; the spread is judge nondeterminism, and ±1 point is the honest tolerance.
Three things worth more than the headline: zero false positives across the 254 ordinary prompts; precision rose while recall nearly quadrupled, so the gain wasn't bought with false alarms; and the adjudicator is escalate-only — it can raise a risk score and never lower one, verified against stub judges hardwired to return "benign."

The raw --out JSON is not committed. From .gitignore, verbatim: "Regenerated by a documented command, and they embed corpus text, so they are reproduced rather than tracked." The eval corpora are committed and linked above. Regenerate both rows with the commands the README specifies:

python benchmark.py \
  --attacks eval/attacks_test.jsonl \
  --benign  eval/benign_test.jsonl \
  --threshold 50 --sweep --out fast_test.json

python benchmark.py \
  --attacks eval/attacks_test.jsonl \
  --benign  eval/benign_test.jsonl \
  --threshold 50 --sweep --adjudicator \
  --band 0 65 --out deep_test.json

python compare_runs.py fast_test.json deep_test.json \
  --threshold 50

The floor has to be 0, not a positive number: 263 of the 500 attacks score exactly 0.0 on the fast path, so a band starting above zero would silently exclude more than half the attack corpus.
Known failure mode

81 of 746 adjudications abstained — every single one of them on an attack. Traced to the model provider's own safety layer declining to classify attack text at all. An attacker who can reliably trigger that refusal drops the request back to the rule layer, where recall is 16.2%. The abstention isn't a neutral outcome. It's the bypass.

Security Intelligence RAG

cyber-griffith/security-intel-rag ↗

Retrieval over the full NVD corpus, with exploitation signal

358,170 NVD CVE records, 1999 through 2026, ingested reproducibly: verified feed hashes, resumable embedding, incremental refresh, and a committed manifest recording exactly which release was pulled and what got filtered out.

Enriched with CISA KEV and FIRST EPSS, so it answers which vulnerabilities are actually being exploited rather than which ones merely score high.
Retrieval was chosen by a four-configuration ablation — BM25, dense, hybrid, and hybrid + cross-encoder rerank — on a pinned sample, compared with exact McNemar tests instead of eyeballed averages, under a decision rule written down before the run. The rule fired: hybrid + rerank and BM25 came out statistically equivalent on answer quality, and the preregistered consequence was to flip the default to BM25 on latency grounds.

Read consequence carefully: it is the rule's stated consequence, not a record of what happened. What happened is in PREREGISTRATION.md, verbatim: "The default is left unchanged and this paragraph is the record of the rule not being executed as written."

I declined that consequence, and wrote down why in the same document. The experiment covered one query shape of four. On product + version queries — the shape where the two configurations measurably differ — hybrid + rerank wins R@1 0.306 to 0.235 at p = 0.0125. Executing the rule would have traded a significant 7-point loss on a shape the experiment never tested for 12.5% latency.

A preregistered rule is only binding over what it measured. Recording the override beats both silently ignoring the rule and following it off a cliff.

A prompt defect cut unsupported claims from 31.2% to 0.7% — one unsupported answer in 143, and that 0.7% was measured on held-out questions the fix had never seen, which is the only version of that claim worth making. The denominator is 143 here and 142 above because the figure above is paired: it counts only the questions both retrieval configurations answered, where this one counts every answer the holdout run graded.

Known failure mode

Those two bars are the limitation. Across the same 142 questions, 99.3% of answers were grounded while the target CVE was retrieved for only 78% — so the system can return a faithful, correctly-cited, confidently-worded answer about the wrong vulnerability. High groundedness on a bad retrieval is more dangerous than a visible refusal, because nothing about the output looks wrong.

Red Team Attack Simulator

cyber-griffith/red-team-simulator ↗

Multi-agent LLM red-teaming harness, run in CI

It profiles a target model, generates adversarial prompts from a 40-technique taxonomy, escalates over multiple turns under five APT personas — APT28, APT29, Lazarus Group, Volt Typhoon, Scattered Spider — and routes every result past an independent LLM judge before it's allowed to count as a finding. Techniques carry OWASP LLM Top 10 (2025) and MITRE ATLAS IDs on the technique record itself, so coverage is queryable rather than asserted.

    severity=Severity.CRITICAL,
    owasp="LLM01:2025",
    mitre_atlas=["AML.T0051", "AML.T0051.001"],

# NIST AI RMF is referenced for MEASURE-function
# coverage, not as a per-technique field.
The whole thing runs in GitHub Actions and gates on critical findings.
The committed run is 1,824 attack executions across seven targets. Three of those sit on the same Bedrock base model, which is what makes the guardrail comparison worth anything — same model, same prompts, matched by technique, so the only variable left is the guardrail.

Known failure mode

This is one operator's taxonomy against a small set of targets — not an industry benchmark, and not a general finding about guardrail products.
